# Native Alignment Pipeline

## Outcome and Scope

October 11, 2026. **iLyric now separates vocals and aligns lyrics natively on macOS, without Python, and reproduces the Python reference exactly on a complete recording.** The separated-vocal CTC pipeline described in [Separated-Vocal Acceptance](separated-vocal-acceptance.md) and [Word-Level Alignment](word-level-alignment.md) was ported to Swift with Core ML, following the plan in [Core ML Port Feasibility](core-ml-port-feasibility.md). On the separated vocals of a five-minute recording, all 72 line estimates and flags and all 501 word boundaries equal the Python pipeline's. The HTDemucs weights are rebuilt on the user's Mac from the official checkpoint and are never redistributed.

Measurements: Apple M4, macOS 27.0.1, Core ML on the CPU unless stated.

## Components

- **AlignmentCore** (Foundation only): lyric sources and canonical text, CTC targets, analysis windows and frame ownership, the forced CTC Viterbi path, greedy decoding, a port of `difflib.SequenceMatcher.ratio`, line proposals, word grouping, vocal activity levels, and the version 2 vocal rules. A fixture generated by the Python reference from synthetic inputs (`scripts/generate_alignment_fixture.py`) fixes spans, proposals, flags, word intervals, estimates, windows, and ratios exactly, and diagnostics to 10⁻¹².
- **Recognition**: wav2vec2 through Core ML, with the feature extractor's per-window normalization outside the network.
- **Separation**: the HTDemucs short-time Fourier transform and its inverse with Accelerate, the `apply_model` segment scheme with centered padding and triangular weights, track normalization, mean downmix, and a port of SciPy's `resample_poly`. Fixtures from Demucs, PyTorch, and SciPy (`scripts/generate_separation_fixture.py`) verify the transforms to 10⁻⁶ and the resampler to 10⁻¹².
- **Weight installation**: `scripts/build_separation_template.py` produces, on the maintainer's machine, the converted network without weights, a zero-filled weight skeleton (3.0 MB compressed), and a recipe for every entry. It refuses to build unless each entry is either derived from the checkpoint or byte-identical in a conversion with random weights. On the user's Mac, `SeparationInstaller` verifies the checkpoint's SHA-256, reads it with a restricted zip and pickle reader that executes no code, applies the recipe (499 tensors, 16 row slices, and the frequency embedding computed in float32), verifies the rebuilt weight file's SHA-256 against the reference conversion, and compiles the model. Installation took 0.7 s.

## Determinism

Core ML execution on the GPU or Neural Engine was not reproducible. Two separations of the same recording with all compute units differed by up to 9×10⁻⁴ (74 dB SNR), and the resulting alignments differed: two line boundaries moved by 0.34 s and four word boundaries by up to 1.02 s. CPU and GPU execution was also not reproducible, whereas CPU-only execution produced byte-identical vocals in repeated runs. Both models therefore default to the CPU.

| Stage | CPU Only | All Compute Units (Not Reproducible) |
| --- | ---: | ---: |
| Separation, 318.7 s recording | 44–56 s | 26–27 s |
| Recognition and alignment | 15.5 s | 4–6 s |

With CPU separation and CPU recognition, every line estimate, flag, and word boundary equals the Python pipeline run on the same decoded mixture. The Python pipeline itself took about 13 s for recognition and longer for separation; its separation is also not bit-reproducible across runs.

## Limitations

The parity results come from one recording, decoded by FFmpeg exactly as the Python pipeline decodes it; decoding with AVFoundation has not been compared. The recognition model is not yet installed from the published Hugging Face files, and the converted packages are not distributed. Neither the single `ilyric` command nor packaging is implemented.

Neither release readiness nor native iOS 27 Music fidelity is established.
