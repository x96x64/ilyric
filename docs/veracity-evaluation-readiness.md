## Environment and Minimal Dependency Plan

Current inspection confirms Apple M4, 16 GiB RAM, arm64, macOS 27.0.1, isolated Python 3.12.14, PyTorch 2.8.0, NumPy 2.5.3, SciPy 1.18.1, librosa 1.0.0, resampy 0.4.3, and soundfile 0.14.0. `torchaudio` is absent. These are current runtime observations; none establishes candidate execution compatibility.

The pinned [environment declaration](https://github.com/CPJKU/veracity/blob/0983900f136173015f3c5d0b116be014edd33905/environment.yml) uses Linux-oriented Python 3.8, torch 1.7.1, torchaudio 0.7.2, librosa 0.8.0, and older numeric packages. [PyPI torch metadata](https://pypi.org/pypi/torch/1.7.1/json) and [torchaudio metadata](https://pypi.org/pypi/torchaudio/0.7.2/json) list macOS x86_64 wheels, not native arm64 wheels. Installing that complete environment would introduce obsolete compatibility and resource risks. TensorFlow, Nussl, audioLIME, notebooks, adversarial analysis, and separators are not required for the selected forward path; no training or explanatory framework is proposed.

The smallest proposed environment uses the existing isolated CPU runtime read-only and a separate, explicitly selected package overlay for **torchaudio 2.8.0**. [PyPI metadata](https://pypi.org/pypi/torchaudio/2.8.0/json) verifies a CPython 3.12 macOS 11+ arm64 wheel, 1,856,736 bytes, requiring torch exactly 2.8.0. Its SHA-256 is recorded in [readiness evidence](alignment-data/v5/readiness.json). The metadata identifies BSD licensing; the [tagged source license](https://github.com/pytorch/audio/blob/v2.8.0/LICENSE) specifies BSD 2-Clause. Retain and inspect the actual wheel notices after authorized acquisition. No wheel contents, installed size, import behavior, or checkpoint load were tested. A future isolated `--target` installation with a pinned hash, disabled dependency resolution, and explicit subprocess search path avoids mutating the existing environment or duplicating PyTorch. Stop if additional binary dependencies are required; do not compile obsolete packages or alter global installations.

[Official torchaudio compatibility documentation](https://docs.pytorch.org/audio/2.8.0/installation.html) requires matching PyTorch releases. Its FFmpeg I/O compatibility does not include the installed FFmpeg 8 series; the proposed path therefore avoids torchaudio I/O and uses the existing librosa/soundfile decoder. No SoX installation is proposed. The source's legacy backend-selection call must be isolated from the new inference-only path after approval. This is a planned small compatibility adaptation, not an implemented adapter.

Preprocessing equivalence is an unresolved execution prerequisite. Preserve mono float32 decoding, 22,050 Hz, [librosa 0.8's `kaiser_best` resampling behavior](https://github.com/librosa/librosa/blob/0.8.0/librosa/core/audio.py) explicitly rather than current defaults, 1,024-sample magnitude STFT, 315-sample hop, Hann window, centering and reflection padding, the checkpoint's custom `mel_orig` filterbank, log transform, zero-mean first convolution, batch-normalization state, 115-frame context, and edge padding. [The source](https://github.com/CPJKU/veracity/blob/0983900f136173015f3c5d0b116be014edd33905/svd/core/audio.py) and [configuration](https://github.com/CPJKU/veracity/blob/0983900f136173015f3c5d0b116be014edd33905/dataset/jamendo/models/model_log_0mean/model.vars) define these requirements. Verify old/new resampler and STFT behavior on synthetic signals before recording candidate scores; do not substitute generic mel features or assume numerical parity. Load only a strict state dictionary on CPU with restricted weight loading; stop rather than falling back to arbitrary pickle execution. Serialization compatibility remains untested.
